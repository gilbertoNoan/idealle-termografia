CONFIGURAR O BANCO COMPARTILHADO (FIREBASE) — PASSO A PASSO
==============================================================
(100% no plano gratuito — sem cartão de crédito, sem Storage)

1) CRIAR O PROJETO
   - console.firebase.google.com → "Adicionar projeto"
   - Dê um nome (ex.: idealle-termografia) → pode desmarcar o Google Analytics → Criar projeto

2) ATIVAR O FIRESTORE (onde ficam os pontos, empresas, OS e também as fotos)
   - Menu lateral → Compilação → Firestore Database → "Criar banco de dados"
   - Modo: "Produção"
   - Região: southamerica-east1 (São Paulo)
   - Depois de criado, vá na aba "Regras" e substitua tudo por:

     rules_version = '2';
     service cloud.firestore {
       match /databases/{database}/documents {
         match /{document=**} {
           allow read, write: if true;
         }
       }
     }

   - Clique em "Publicar"

   OBS: o Firebase Storage NÃO é usado neste projeto (ele exige o plano pago
   Blaze). As fotos são comprimidas no próprio navegador e salvas como
   documentos comuns na coleção "fotos" do Firestore — sem custo, dentro do
   plano gratuito (Spark).

3) PEGAR AS CHAVES DE CONFIGURAÇÃO
   - Vá em Configurações do projeto (ícone de engrenagem, topo do menu lateral)
   - Na aba "Geral", desça até "Seus apps" → clique no ícone "</>" (Web)
   - Dê um apelido (ex.: termografia-web) → "Registrar app"
   - Vai aparecer um bloco assim:

     const firebaseConfig = {
       apiKey: "AIzaSy...",
       authDomain: "idealle-termografia.firebaseapp.com",
       projectId: "idealle-termografia",
       storageBucket: "idealle-termografia.firebasestorage.app",
       messagingSenderId: "123456789",
       appId: "1:123456789:web:abcdef"
     };

   - Copie esse bloco inteiro

4) COLAR NO ARQUIVO index.html
   - No GitHub, abra o repositório idealle-termografia
   - Clique em index.html → ícone de lápis (Edit) no canto superior direito
   - Use Ctrl+F (ou Cmd+F) e procure por: FIREBASE_CONFIG
   - Substitua os 6 valores pelos que você copiou no passo 3 (mantendo as aspas)
   - Role até o final da página → "Commit changes"
   - A Vercel redeploya sozinha em ~1 minuto

PRONTO. A partir daí:
   - Qualquer aparelho que abrir o link principal (index.html) e salvar um ponto,
     esse ponto (e as fotos) aparece pra todo mundo que abrir o mesmo link.
   - Para dar acesso a um cliente, mande o link assim:
     https://SEUSITE.vercel.app/?cliente=Nome Exato Do Cliente
     (o "Nome Exato Do Cliente" tem que ser IGUAL ao que você digita no campo
     "Cliente" quando cria os pontos daquela empresa)
   - Ou gere o link de uma OS específica direto pelo botão "🔗 Link do cliente"
     dentro da própria OS, na aba "Ordens de Serviço".

LIMITE A SABER (fotos no Firestore em vez de Storage)
--------------------------------------------------------------
Cada documento do Firestore tem um limite de 1 MB. As fotos são comprimidas
automaticamente antes de salvar (redimensionadas e convertidas pra JPEG de
qualidade reduzida) para ficarem bem abaixo desse limite — na prática isso
significa fotos de boa qualidade pra visualização e para o PDF, mas não os
arquivos originais em resolução máxima da câmera.

SOBRE SEGURANÇA (leia antes de usar com clientes de verdade)
--------------------------------------------------------------
A regra acima ("allow read, write: if true") deixa o banco aberto: qualquer
pessoa com o link — ou até sem o link, se souber o endereço técnico do banco —
consegue ler e, tecnicamente, também escrever nele. Isso é aceitável para
começar e testar, mas não é uma proteção de verdade.

Para uso com clientes reais, o recomendado é:
- Trocar o link "?cliente=Nome" por um código aleatório único por cliente
  (em vez do nome exato, mais difícil de adivinhar); e/ou
- Adicionar login (Firebase Authentication) para os clientes, e regras que só
  liberam a leitura dos dados daquele cliente autenticado.

Se quiser, eu implemento qualquer uma dessas duas opções — é só pedir.
